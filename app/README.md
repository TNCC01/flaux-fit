# FIT by Flaux - Native App Runbook

The store app for FIT, on the App Store (iPhone and iPad) and Google
Play. Free, nothing to buy, no ads, no account. Apple Health from v1.
The website at fit.flaux.com.au stays exactly as it is and stays free.

## How this folder works

- The website at the repo root is the single source of truth.
- `node sync.mjs` copies it into `www/` and adds `native-bridge.js` to the
  app's copy of `index.html` only. Never edit `www/` by hand; it is made.
  It also checks every file the website keeps for offline use made it
  into `www/`, and stops if one didn't.
- `native-bridge.js` does nothing unless Capacitor says it's the native
  app, so the website never runs a line of it. `.vercelignore` keeps this
  whole folder off the website.
- `ios/`, `android/`, `www/`, `keys/` and `node_modules/` are git-ignored
  by design: the native projects are generated by `npx cap add` on the
  Mac, and `keys/` holds signing material that must never be committed.
- `package-lock.json` is committed, so the TestFlight build and the
  release build (and every one after) get exactly the same Capacitor and
  plugins. Install with `npm ci`, which follows it. To update a plugin,
  `npm install <name>@<version>`, then commit the lock file with it.

## What the app adds to the website

All of it in `native-bridge.js`, from the outside: `js/app.js` has no
idea it's in an app, and nothing on the website changed for it.

| | |
|---|---|
| No service worker | The files are in the app and updates come through the store, so FIT is shown a browser without one (no "New version ready" bar). |
| No browser bits | The Add to Home Screen hint and Full screen button are hidden. Your data says the app keeps its own data, apart from the website. |
| Share | Workout links go through the share sheet (Share plugin) and point at https://fit.flaux.com.au, not the app's own address. |
| Backups | Save a backup writes the file to the app's cache and opens the share sheet (Files, iCloud Drive, AirDrop; Google Drive on Android). |
| Screen on | From Start to the finish, pauses included, through KeepAwake; let go at the finish and on leaving the workout. |
| Haptics | A firm tap as work starts, a softer one for every other phase, a light tick on 3, 2, 1, and a success tap at the finish. Even on No sound. (iPads have none.) |
| Apple Health | iPhone and iPad: asks after the first finished workout, then saves each one (see below). A "Save to Apple Health" switch joins the settings under the workout. |
| Android back | Closes a sheet, else does the screen's own Back (Menu's two taps mid-workout), and on the home screen puts the app away. |
| Privacy and support | Links to the privacy policy and support pages at the foot of Your data (Saved & ready-made), and to the privacy policy on the Apple Health question. Apple wants the privacy policy inside the app as well as in the listing (guideline 5.1.1). They open in Safari or Chrome. |

### Apple Health

FIT's own plugin, `plugins/fit-health/` (installed from `package.json` as
`fit-health`, a local `file:` package):

- Asks for write access to **Workouts only**, and reads nothing.
- Saves each finished workout as an `HKWorkout` through `HKWorkoutBuilder`
  (the current API; `HKWorkout`'s initialisers are deprecated from iOS 17):
  the type, a start and an end. No calories or heart rate: FIT doesn't
  measure them, so it doesn't make them up.
- Types: Short bursts and Long efforts are **High Intensity Interval
  Training**; EMOM, AMRAP, For Time and the Surf check are **Functional
  Strength Training**; a mix of styles is **Cross Training** (Apple's
  "any mixture of cardio, strength and flexibility"); stretching is
  **Flexibility**. The table is `ACTIVITY` in `native-bridge.js`.
- The workout ends when it finished and starts the minutes FIT's clock
  ran before that, so a pause for water isn't counted as exercise.
- A session skipped through inside its first minute isn't saved, and
  neither is one left part-way.
- iOS only. Android has no native side, so no switch or question shows
  there. Health Connect is v1.1.

**`FitHealthPlugin.swift` has never been compiled**: it was written on
Linux against the HealthKit and Capacitor 8 APIs. The first Xcode build
is its first compile. If Xcode shows an error in it, paste the error to
Claude.

## One-time setup (your side)

1. **Apple Developer** (developer.apple.com > Certificates, Identifiers &
   Profiles): Identifiers > + > App IDs > App, Bundle ID
   `au.com.flaux.fit.app`, description "FIT by Flaux", and tick
   **HealthKit**. Then Profiles > + > App Store Connect, that App ID,
   your Apple Distribution certificate, named **FIT by Flaux App Store**
   (the name `build/ExportOptions.plist` expects).
2. **App Store Connect**: Apps > + > New App: iOS, name FIT by Flaux,
   language English (Australia), the bundle ID above, SKU `fit-by-flaux`.
   Copy the app's Apple ID (the number in its URL) into `FIT_ID` in
   `app/scripts/asc-common.mjs` and commit it. Then, from the repo root:
   `node app/scripts/asc-price-age.mjs --issuer <uuid> --apply` (Free,
   and the age rating answers in `listing-kit.md`).
3. **Google Play Console**: Create app: FIT by Flaux, app, free. Then
   Setup > API access: give the same service account as Survival release
   access to FIT (or make one), and save its JSON key as
   `app/keys/fit-play.json` (git-ignored).

## Build (on the Mac)

```bash
cd app
npm ci
node sync.mjs
npx cap add ios      # first time only
npx cap add android  # first time only
npx @capacitor/assets generate --ios --android
npx cap sync
node scripts/bump-native-versions.mjs --version 1.0.0 --android-code 1 --ios-build 1   # first time only
npx cap open ios
```

The icon and splash sources are in `assets/` (made by `node
make-assets.mjs` from the website's own kettlebell in `favicon.svg`):
teal to the edges for the icon, FIT's dark background for the splash.

From then on, after any change to the website: `node sync.mjs && npx cap sync`.

### Xcode, once, after `npx cap add ios`

1. App target > Signing & Capabilities: team `3CCPC6S9PP`. Then
   **+ Capability > HealthKit**. Leave Clinical Health Records and
   Background Delivery off. (This makes `App/App.entitlements`.)
   Then check Xcode hasn't also made Health a requirement, from `app/`:

   ```bash
   plutil -extract UIRequiredDeviceCapabilities json -o - ios/App/App/Info.plist
   ```

   It should print `["armv7"]` (or say there's no such key). If
   `"healthkit"` is in it, take it out (`plutil -remove
   UIRequiredDeviceCapabilities.1 ios/App/App/Info.plist`, where 1 is its
   place in the list counting from 0, then run the check again). With it
   there, the App Store keeps FIT off every iPad without the Health app,
   though FIT works fine without Health. Check it before the first
   upload: device requirements are hard to change once an app is out.
2. The Info.plist strings Apple shows on its Health permission sheet,
   plus the export compliance answer, from `app/`:

   ```bash
   plutil -insert NSHealthUpdateUsageDescription -string "FIT adds each workout you finish to Apple Health: the kind of workout, when it started and how long it ran." ios/App/App/Info.plist
   plutil -insert NSHealthShareUsageDescription -string "FIT never reads anything from Apple Health. It only adds the workouts you finish." ios/App/App/Info.plist
   plutil -insert ITSAppUsesNonExemptEncryption -bool NO ios/App/App/Info.plist
   ```

   `NSHealthUpdateUsageDescription` is the one FIT needs (writing).
   `NSHealthShareUsageDescription` is for reading, which FIT never asks
   for, but App Store Connect's upload check can still flag an app that
   uses HealthKit without it, so it's there, saying so plainly.
3. Orientations: the template already allows all four on iPad and
   portrait plus both landscapes on iPhone. Leave **Requires full
   screen** off, so the iPad keeps Split View and Stage Manager.
4. **Background audio: not needed, leave it off.** FIT keeps the screen
   on through a workout, so it never runs in the background, and its
   clock catches up from the wall clock whenever it comes back. Asking
   for the audio background mode without playing audio all the time is
   a common rejection (guideline 2.5.4).

### Android, once, after `npx cap add android`

Release builds are signed with the same upload keystore as Survival and
MiPixArt (Play App Signing holds the real key; an upload key can serve
several apps). Copy `android/app/upload-keystore.jks` and
`android/keystore.properties` from the Survival checkout into
`app/android/` (same places), and copy the `keystoreProperties` lines and
the `signingConfigs { release { ... } }` block, with
`signingConfig signingConfigs.release` under `buildTypes { release }`,
from Survival's `android/app/build.gradle` into FIT's. Do not regenerate
the key.

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
cd app/android && ./gradlew bundleRelease
```

## Check it on the devices

Run it from Xcode on each of these (choose the destination, then Run):

- **The iPad, in landscape** in its keyboard folio. Rotate it to be sure
  nothing is stuck in portrait.
- **An iPhone**, portrait and landscape.
- **The iPhone Duo simulator**: in Xcode 27.1's Device Hub, add an
  iPhone Duo simulator and run on it, opened flat (951 x 669 pt, the
  crease down the middle) and folded. Opened flat, the app has the
  whole inner screen, taller than Safari's 585 to 620 pt, so check the
  layout uses it, and that nothing you read or tap during a workout sits
  on the crease.
- **An Android phone** (Android Studio > Run, or `npx cap run android`).

On each, go through:

- [ ] Home, Start a workout, the 3D figures move, tap one for the viewer.
- [ ] Airplane mode on: the app opens, builds a workout, and the 3D viewer works.
- [ ] The screen stays on through a whole workout, a pause included, and sleeps as normal after.
- [ ] Haptics on each phase and on 3, 2, 1 (iPhone and Android; the iPad has none).
- [ ] **Sound, on an iPhone with the silent switch on**: "Beeps even on silent" should be heard, "Beeps over my music" shouldn't, and with Spotify playing, "Beeps over my music" should leave it playing. FIT does this with Safari's audio session API; if the app's web view doesn't honour it, the fix is native (the audio session in `AppDelegate.swift`): tell Claude what you heard.
- [ ] Voice coach on the iPhone and iPad. On Android, expect the voice coach switch to be missing: Android's web view has no speech synthesis (FIT checks and hides it). The beeps still work.
- [ ] Share: the link starts `https://fit.flaux.com.au/#w=` and opens the same workout on another phone.
- [ ] Save a backup goes to the share sheet; Copy to another device, then Restore in the app, brings the website's data across.
- [ ] Apple Health (a real iPhone or iPad; the Simulator has the Health app too): finish a workout (let it run at least a minute), tap Save to Apple Health, allow Workouts. It says "Saved to Apple Health.", and the Health app shows it under Browse > Activity > Workouts with FIT's icon. Turn the switch off, finish another: nothing new in Health.
- [ ] Android: the back gesture closes a sheet, goes back a screen, asks twice mid-workout, and puts the app away from home.

Without a device, the bridge's behaviour is tested in a browser with a
stand-in for Capacitor:

```bash
npm install && npx playwright install chromium   # at the repo root, once (the browser suite's)
cd app && npm test                                # node sync.mjs, then node test-bridge.mjs
```

Run it after any change to `js/app.js`: the bridge wraps a few of its
functions by name (listed at the top of `native-bridge.js`), and the
test fails if one goes missing or changes what it does. GitHub's checks
run it on every pull request too (`node app/sync.mjs && node
app/test-bridge.mjs`, after the browser suite), so a change to the
website that breaks the app shows up before it's merged.

## Release

Before submitting to either store:

- **Landscape layout A is the website's default**, not the trial. The
  app opens at `/` and never has a `?land=`, so while the trial's default
  is `off` (see LANDSCAPE, A TRIAL in `js/app.js`), the app would have
  the old layout on the iPad and the iPhone Duo. Build the release from a
  website with A on for everyone. (A TestFlight build before then is
  fine for trying the rest: five quick taps on the word Text under a
  workout bring up the Landscape buttons, as on the Home Screen.)
- **The privacy and support pages are live.** They're new on this
  branch, both stores check the URLs at submission, and the app links to
  them. Merge to `main`, let Vercel deploy, then open
  https://fit.flaux.com.au/privacy.html and
  https://fit.flaux.com.au/support.html and check both load. Then submit.
- **Where else it's offered.** App Store Connect also offers an iPhone
  and iPad app on Apple Silicon Macs and Apple Vision Pro, ticked by
  default (Pricing and Availability). FIT has never been run on either,
  nor its Apple Health and haptics, so untick both for 1.0 unless you've
  tried it there. The website already does the job on a Mac.

Then:

1. Listing: paste `listing-kit.md` into both consoles (App Privacy: Data
   Not Collected; Play Data safety: no data collected or shared; the
   Health apps declaration), and upload the screenshots
   (`asc-upload-screenshots.mjs`; `play-publish.mjs upload-graphics`).
2. iOS: `node app/scripts/asc-release.mjs ship --issuer 543fc29c-c28d-4ac3-9078-87959e3b417c --build 1 --version 1.0.0`
   attaches the build, declares no non-exempt encryption, and submits it.
3. Android: `node app/scripts/play-publish.mjs promote 1` (production,
   full rollout). A first release on Play needs the content rating,
   target audience, Data safety and Health apps forms done first.
4. Expect Apple review in 1 to 2 days (Apple Health apps get a careful
   look at the permission wording and the privacy policy), and Play
   longer for a first release.

Later releases: merge the branch, then from the checkout that has the
native projects, `node app/scripts/bump-native-versions.mjs --check`,
bump (`--version 1.0.1 --android-code 2 --ios-build 2`), `node sync.mjs &&
npx cap sync`, and the same build and upload steps.

## The store scripts (`app/scripts/`)

Survival's, pointed at FIT. The App Store Connect ones share
`asc-common.mjs`, which holds the app id (a placeholder until step 2 of
One-time setup; until then each takes `--app <id>`) and reads the same
`AuthKey_*.p8` as Survival's.

| Script | Does |
|---|---|
| `asc-price-age.mjs` | Price Free, and the age rating answers |
| `asc-testflight.mjs` | Internal TestFlight group, and adds a tester |
| `asc-upload-screenshots.mjs` | Uploads screenshot sets |
| `asc-release.mjs` | `status`, and `ship` (attach a build, What's New, submit) |
| `play-publish.mjs` | `upload-aab` (internal), `promote` (production), `upload-graphics` |
| `bump-native-versions.mjs` | The Mac-local version numbers, both platforms |

Left out from Survival, because FIT has nothing to sell: RevenueCat and
`store-bridge.js`, the paywall and the redeem-a-code button (and their
tests), `create-iap` in `play-publish.mjs`, `asc-finalize.mjs` (it
attached the purchase's review screenshot), and `@capacitor/app-launcher`
(it opened the other Flaux app's store page).

## Later

- **Health Connect on Android** (v1.1): an Android side for
  `plugins/fit-health`, and Play's Health Connect declaration.
- **A lock-screen countdown (Live Activities)**: left out of v1. It needs
  a Widget Extension target with its own Swift and an App Group, which
  `npx cap add` doesn't make and nothing here can build or test, and
  `@capgo/capacitor-live-activities` needs the same extension.
- **FIT links that open the app**: Associated Domains in Xcode, an
  `apple-app-site-association` file on the website (a change to the
  site), and the bridge listening for `appUrlOpen` to put the link's
  `#w=` into the address, where FIT already looks for one.
- **The voice coach on Android**: a text-to-speech plugin behind FIT's
  `speechSynthesis` calls.
- If anyone ever loses their data to iOS clearing the web view's
  storage, mirror FIT's prefs into native storage (`@capacitor/preferences`).
